## 0.2 共用铁律

1. **全程自行决策，不要提问。** 歧义按优先级取值：**参考程序运行态实测 > `images/` 截图 > `docs/界面规格表.md` > 现有实现**。
2. **运行态优先于代码阅读**。代码只是线索，结论必须来自真实运行。
3. **禁止以 mock 作为证据**。`public/preview-bootstrap.js` 的假 IPC 只能用于纯视觉预览；所有功能结论必须在 `npm run tauri:dev` 或 `dist-portable/navkit.exe` 上取得。
4. **禁止假成功**。不允许用假进度条、`setTimeout` 假装完成、写死演示数据、静默 `catch` 掩盖错误。
5. **禁止死入口**。可见入口只能落在三类之一：真实可用 / 明确禁用（灰 + 可读原因）/ 已删除。
6. **资源合规**。不得从参考程序或安装包提取图标、位图、字符串资源；图标一律自绘 SVG；文案可逐字对齐（事实性描述），不得复制商标图形。
7. **不做无关重构**。为解决问题而改，不为"顺便优化"而改；重构需单独提交并全量回归。
8. **数据安全**。所有破坏性操作只在专用测试库 `navkit_parity` / `testdata/*.db` 上执行。
9. **不许粉饰**。禁止"基本可用""大体一致""影响不大"。有偏差写偏差，有缺口写缺口。
10. **可复现**。任何结论必须附「复现命令 + 输出 + 证据文件路径」，他人照做能得到相同结论。

# 第一部分 · 缺陷修复任务书

## 1. 工作方式（补充约束）

1. **必须真实运行验证**，不接受"代码看起来对"。每项修复给出可复现操作路径与结果证据。
2. **最小改动、保留架构**：不引入新运行时依赖，不重写 UI 框架；新增 npm/crate 依赖需说明理由。
3. **不许静默失败**：IPC/后端错误必须转成用户可见提示，禁止 `catch { /* ignore */ }` 后什么都不显示。
4. **不破坏既有能力**：树、查询执行、网格编辑、导入导出、传输、转储、备份、用户、自动运行、模型、图表均需回归通过。

## 2. 开工前必须处理的 3 个前置问题（会造成大面积"功能不可用"）

### P0-1 缺少 Tauri 2 capabilities → 窗口控制、文件选择器被 ACL 拒绝

- **现状**：`src-tauri/` 下无 `capabilities/*.json`，`src-tauri/gen/schemas/capabilities.json` 为 `{}`。
- **后果**：`getCurrentWindow().minimize()/toggleMaximize()/close()`、`onCloseRequested`、`plugin-dialog` 的 `open()/save()` 全部被拒；前端用空 `catch` 吞掉，表现为"按钮点了没反应"。
- **要求**：新增**最小权限** capability（`core:window:allow-minimize`、`allow-toggle-maximize`、`allow-close`、`allow-start-dragging`、必要事件监听权限、`dialog:allow-open`、`dialog:allow-save`），只授权实际用到的命令。
- **验收**：DevTools 无 ACL deny 报错；三个窗口按钮全部生效。

### P0-2 开发模式跑的是 mock 页，真实后端根本没被调用

- **现状**：`src-tauri/tauri.conf.json` 的 `devUrl` 指向 `http://localhost:5183/preview.html`，而 `preview-bootstrap.js` 注入了整套假 IPC。
- **后果**：`tauri:dev` 下所有 `api.*` 命中 mock —— "很多功能不能用"却查不出原因。
- **要求**：`devUrl` 改为 `http://localhost:5183/index.html`；mock 仅保留给浏览器纯视觉预览，并在代码注释与报告中写明两者区别。

### P0-3 错误不可见

- **要求**：统一 `api.call` 错误出口，加全局 `unhandledrejection` 兜底，失败必弹提示；空 `catch` 要么删除、要么补提示与日志（`storage::log_line`）。

## 3. 用户报告的 11 个问题（逐条细化）

### U1 数据源配置：端口改不了，对话框样式不对

- **现象**：新建连接时端口框输入任何值都被立刻重置为类型默认端口；对话框样式与参考截图不一致。
- **线索**：`src/dialogs/ConnectionDialog.ts` 的 `applyKind()` 中 `if (!isSqlite && (!isEdit || !userTouchedPort))` —— 新建连接时 `!isEdit` 恒为真，每次 `input` 都把端口写回默认值。
- **期望**：新建时按类型给默认端口，**用户一旦编辑就永不再覆盖**；类型切换仅在"用户未手改端口"时跟随默认值；非法端口（空/非数字/<1/>65535）内联报错并阻止保存；数字框滚轮不误改。
- **样式**：按参考截图对齐宽度、页签（常规/高级/数据库/SSL/SSH/HTTP）、控件高度、字号 10.5px、行距、字段对齐；"测试连接"位置与状态（测试中/成功/失败）明确。
- **验收**：新建 MySQL 改端口 3307 → 保存 → 重开仍为 3307 → 测试连接打到 3307；编辑已有连接同样生效。

### U2 数据同步不可用

- **现象**：`TabKind` 有 `"datasync"`、`TabStrip` 有图标分支，但无创建入口，`commands.rs` 无对应命令 —— 空壳。
- **期望**：提供「数据同步」入口（Ribbon + 工具菜单），实现表级同步：源/目标（连接+库+表）、字段映射、匹配键、插入/更新/删除策略、差异预览、进度、结果报告。
- **验收**：A 库→B 库同步一张表，行数与抽样一致；重复执行幂等（按匹配键更新而非重复插入）；中途失败有回滚或明确部分失败报告。

### U3 SQL 查询界面智能提示不好用

- **期望**（`src/ui/SqlEditor.ts`，CodeMirror + `completionData`）：
  - 关键字、函数、库名、当前库表/视图、已展开连接的表；
  - `别名.` 立即列字段；`FROM ` 后列当前库表；`WHERE ` 后优先列字段；
  - 补全项带类型标签/图标，前缀优先排序，大小写不敏感；
  - `Ctrl+Space` 手动唤起；无匹配不弹空白框；错误上下文不弹；
  - 大库（1000+ 表）不卡顿（元数据缓存 + 去抖，勿每次按键走 IPC）。
- **验收**：`SELECT * FROM dbswitch_schema_history h WHERE h.` 列出该表全部字段；快速连续输入无卡顿无报错。

### U4 数据列宽不能拖动

- **线索**：`src/ui/DataGrid.ts` `onHeaderMouseDown` 仅在表头右缘 6px 判定；无 hover 光标；`setData` 列名变化即重置 96px，刷新/翻页后丢宽。
- **期望**：分隔线 hover 显示 `col-resize`；拖拽实时改宽且**不触发排序**；最小 40px；双击分隔线自适应；最后一列填满剩余；刷新/翻页/重连后保持（按 连接+库+表+列 持久化）；表头表体严格同步。
- **验收**：拖宽 → F5 刷新 → 宽度不变且未误排序；拖动过程选中态不丢。

### U5 「查询」没有保存 SQL；视图、函数、查询不能用

- **期望**：
  - **查询**：`Ctrl+S` 保存到连接内（可命名），树中"查询"分组列出，双击打开、右键重命名/删除/另存为/复制；关闭有未保存修改时提示；重启后仍在。
  - **视图**：双击查看数据；设计器可编辑 SQL 并保存（`CREATE OR REPLACE` / `ALTER VIEW`），保存后树与信息面板刷新。
  - **函数/存储过程**：双击打开定义（`get_routine_definition`），可编辑保存、可运行；参数与返回值清楚。
  - 全部真实后端持久化（落 `data/`），不是内存态。
- **验收**：新建查询 → 写 SQL → `Ctrl+S` 命名 → 关闭 → 树中出现 → 重启仍在 → 内容一致；改视图 SQL 后 `SHOW CREATE VIEW` 体现。

### U6 打开的数据库图标颜色不变

- **现象**：库节点打开后仍为灰色。
- **线索**：`App.ts` 有 `syncDbIcons()`，需确认调用时机（选中/展开/树重建/刷新后是否都触发，重绘后是否丢状态）。
- **期望**：已打开连接为彩色/绿色，未打开为灰；展开、折叠、切换选中、刷新、重连、重启后均正确。
- **验收**：打开 `dbswitch` → 变绿；关闭连接 → 变灰；重启按打开状态还原。

### U7 新建连接对话框的 logo 要是各自数据库的 logo

- **现状**：`ConnectionDialog.ts` 只引用 `ICON_CONN_MYSQL_LG` 与 `ICON_DATABASE_LG`，不随类型变化。
- **期望**：顶部图标对右侧随类型切换（MySQL/PG/SQLite/TiDB/OceanBase/PolarDB/TDSQL/Doris/openGauss/Kingbase/HighGo/ClickHouse/达梦/Hive 各一张）；左侧为 NavKit 自有 logo；类型下拉旁同时显示小图标。
- **验收**：切换全部类型，两处图标同步，无空白/错图/错位。

### U8 右侧信息面板展示不全、页签不全

- **期望**：页签按对象类型动态给出完整集合（表：常规/字段/索引/外键/检查/触发器/选项/注释/SQL 预览；视图、函数各有对应集合），不少项、不空白。
- **内容**：字段页列全部列（名/类型/长度/小数位/非空/默认值/注释/键）；索引含唯一与非唯一、包含列；SQL 预览生成可执行完整 DDL。
- **布局**：纵向可滚动、横向不截断或换行；滚动条不遮挡末行末列；宽度变化自适应；无数据有空态说明。
- **验收**：打开 `dbswitch_schema_history` 字段页 6 列全部可见；SQL 预览与 `SHOW CREATE TABLE` 语义一致；无外键/触发器对象显示空态。

### U9 菜单栏功能不一致

- **要求**：
  - 菜单栏项与顺序以参考程序实测为准（文件/编辑/查看/表/收藏夹/工具/窗口/帮助；先实测"表"出现的规则，**固定成一致规则**并写入文档）；
  - 修掉重复项（`dump-sql` 同时在"文件"与"工具"）、语义重复 id（`transfer` vs `data-transfer`）、无实现项（如 `print`）——实现、删除或明确禁用；
  - 快捷键与实际绑定一致（`Ctrl+S/Q/N/R/F/H/W`、`F5/F6/F3`、`Alt+F4` 等）；
  - 可用性随上下文切换（无标签页/非表页/非查询页相关项禁用）。
- **验收**：逐项点击，输出"菜单项 → 行为/禁用原因"对照表；所有快捷键实测生效。

### U10 右上角窗口按钮全部无效

- **线索**：P0-1（缺 capabilities）；`decorations: false` 无原生兜底。
- **期望**：最小化、最大化/还原、关闭全部可用；`✕` hover `#E81123` 白字、其余 hover `#E5E5E5`；最大化图标随状态切换；双击标题栏切换；标题栏可拖拽；关闭走 `confirm_on_close` 确认。
- **验收**：三按钮 + 双击标题栏 + 拖拽均正确；控制台无权限报错。

### U11 表页筛选、排序交互不对

- **期望**：
  - 表头单击只选中列（不排序）；排序由排序箭头/工具栏触发；Shift 多列排序并显示序号；升降序指示明确；工具栏同步显示当前排序与筛选。
  - 筛选向导（字段/运算符/值/AND-OR，可多条件增删），应用后显示条件条并可一键清除。
  - **筛选与排序下推 SQL 服务端**，与分页联动：总行数为筛选后的数量，翻页稳定，而非只处理当前页。
  - 列头右键：升序/降序/筛选/隐藏列/列宽自适应。
- **验收**：大表筛选 + 双列排序连续翻页不重不漏；状态栏总行数与条件一致；清除后恢复。

## 5. 通用质量要求

- **布局稳定性**：不同标签页、不同数据量、不同窗口尺寸下，标题栏/菜单/Ribbon/标签条/状态栏高度与主分割位置恒定。
- **状态一致性**：树、Ribbon、菜单、工具栏、状态栏、信息面板反映同一份状态。
- **持久化**：连接、密码（加密）、分组、收藏、最近、列宽、窗口尺寸位置、布局开关均落 `data/`，重启还原。
- **性能**：百万行表分页 ≤1s 首屏；树展开不阻塞 UI；SQL 补全按键延迟 ≤50ms。
- **反馈**：长操作有 loading、可取消（查询有停止）；成功/失败有提示，错误含数据库原始报错。
- **空态与禁用态**：空网格、空树、无连接、未选标签页都有说明文案。

## 13. 缺陷分级

# 第三部分 · 功能对齐任务书

## 17. 角色、目标与"完成"的定义

你是**产品对齐工程师 + 验收测试员**，不是自由发挥的开发者。

目标：把 NavKit 做成**行为上与参考客户端逐项对齐**的产品——同一功能，在同一位置、用同一手势、给出同一反馈、产生同一结果、用同一快捷键、记住同一偏好。界面上**任何看得见的东西都必须能用、好用**。

"1:1"的操作定义（下文称「12 同」）：

> **位置同 · 名称同 · 图标同 · 层级同 · 手势同 · 步骤同 · 反馈同 · 默认值同 · 快捷键同 · 状态同 · 副作用同 · 持久化同**

任一条不满足，该功能的对齐任务不算完成，必须登记差异并给出处置（实现 / 明确禁用 / 删除入口 / 记为已知偏离）。

## 18. 对齐专用铁律

| 编号 | 铁律 |
|---|---|
| P1 | **测量优先于猜测**。每条参考行为都要有实测证据（截图/录屏/控件树 dump/抓到的 SQL）。禁止写"参考程序应该是……" |
| P2 | **运行态为准**。基准是运行中的参考客户端；截图仅作版式与文案辅助 |
| P3 | **只观察行为，不提取资产**。禁止从参考程序安装包/进程/文件中提取图标、位图、字符串资源、字体。图标一律自绘；文案可逐字对齐（事实性描述），不得复制商标图形 |
| P4 | **不动生产数据**。参考程序与实现都只连专用测试库 `navkit_parity`，破坏性操作前重建 |
| P5 | **一致优先，但偏离必须登记**。参考行为优先复刻；刻意不同（如清空密码这类缺陷、破坏性操作加确认）必须写入 `docs/偏离登记.md`，含理由、影响、可回滚方式 |
| P6 | **禁止假对齐**。不得靠禁用、隐藏、写死演示数据、假进度条、`setTimeout` 假装成功来"看起来一致"。隐藏或禁用必须有决策记录与用户可见原因 |
| P7 | **每条结论双向可查**：既能在参考程序复现，也能在 NavKit 复现，且两者证据同屏 |
| P8 | **不做发散重构**。为对齐而改，不为"顺便优化"而改；重构单独提交并全量回归 |
| P9 | **不允许死入口**。可见入口只能落在三类之一：可用 / 明确禁用（灰 + 原因）/ 已删除 |
| P10 | **验收命令可一条重跑**（脚本化），不依赖手动点几十下 |

## 22. 对齐工作流程（每模块固定五步）

1. **采集**：UIA dump + 逐页截图 + 逐手势 SQL 抓包，落 `docs/对齐/<模块>/`。
2. **建表**：写「参考行为表」，每条带维度编号与证据路径。
3. **比对**：填「当前实现行为」，标出差异与维度。
4. **处置**：`FIX` / `DISABLE` / `REMOVE` / `DEVIATE`，`DEVIATE` 必须写偏离登记。
5. **复验**：改完后重跑采集，差异项归零或降级为已登记偏离。

## 23. 对齐专用验收标准

1. §21 全部模块都产出「参考行为表 / 实现行为表 / 差异处置表」，无遗漏模块。
2. 差异项 100% 有处置结论；`FIX` 项全部复验通过。
3. `DEVIATE` 项全部在 `docs/偏离登记.md`，含理由与影响。
4. D1–D15 十五个维度在每个重点模块（连接对话框、数据表格、查询编辑器、表设计器）**逐维打分且有证据**。
5. 数据类功能（分页/排序/筛选/编辑/DDL/同步）必须附参考与实现的 SQL 对照，形态与语义一致（字段名可不同，行为必须一致）。
6. 快捷键、默认值、持久化三项必须逐项实测，不允许推断。
7. 输出「对齐总表」：模块 × 维度 × 结论，一眼可见哪些还不对齐。

# 第四部分 · 反复自证协议（假设你没做完）

## 24. 默认立场（先读三遍）

**我不相信这件事已经完成。**

你的任何"已完成/已修复/已验证/已通过"在没有证据时一律视为**未完成**。你不是来汇报进度的，你是来**用证据击穿自己的结论**的。

每次你想说"好了"的时候，先假设自己错了，然后去找"我是怎么错的"。

> **判定权不在你手里，在证据手里。**

## 25. 五条不可违反的自我审查铁律

| 编号 | 铁律 | 违反即判定本轮全部作废 |
|---|---|---|
| A1 | **不许自我认证**。"我测试过了""我确认过""应该没问题"不是证据。只有**可复现命令 + 输出 + 侧效反查**是证据 | 出现即作废 |
| A2 | **每轮必须换方法**。同一手段重复三遍不算三轮；第二轮必须用与第一轮**机制不同**的手段（手工点击 → 自动化脚本 → DB 侧 SQL 反查 → 日志比对 → 换环境/尺寸/数据库） | 重复即作废 |
| A3 | **必须主动找错**。一轮下来"零问题"= 你的测试方法不够狠，不是代码够好。零问题的轮次不计入轮次，且必须写出「下一轮准备怎么更狠」 | 零问题即作废 |
| A4 | **不许缩小范围**。不能只测 happy path、只测 SQLite、只测 125% DPI、只测当前窗口大小、只测刚改的那一个函数 | 缩范围即作废 |
| A5 | **不许粉饰**。禁止"基本可用""大体一致""影响不大""小问题""可以接受"。有偏差写偏差，有缺口写缺口 | 粉饰即作废 |

## 26. 执行循环（至少 5 轮，每轮必须产出新证据）

```
第 N 轮
├─ 1. 假设未完成：列出本轮要打脸的 5 个"我最没底的点"
├─ 2. 设计反证：为每个点设计一个能把它证伪的实验（不是验证它成立）
├─ 3. 执行实验：真实运行，全程留证
├─ 4. 记录结果：通过/失败，附证据
├─ 5. 修/改/补：只针对失败项动手
└─ 6. 回归：不只回归失败的，要全量回归（防连带破坏）
```

### 每轮方法必须不同（强制轮换表）

| 轮次 | 必用手段 | 专项打击目标 |
|---|---|---|
| R1 | 手工点击（真实窗口，鼠标键盘） | 主流程走通，找出"点了没反应" |
| R2 | 代码静态审计 + 四方命令比对 | 找出"有 UI 无后端""有分支无实现" |
| R3 | 自动化脚本（CDP / tauri-driver）跑全入口点击 | 找出偶发失败、状态残留、重复提交 |
| R4 | **DB 侧反查 + SQL 抓包** | 找出"界面说成功但库里没变""SQL 与预期不符" |
| R5 | **环境矩阵轰炸**（DPI 100/125/150 × 5 种窗口尺寸 × 4 种数据库 × 重启 × 异常注入） | 找出只在特定条件下暴露的崩溃与错乱 |
| R6+ | 自选更狠的手段（并发、限额、超时、断网、脏数据、超长输入、快速连点） | 找出稳定性边界 |

**每轮结束必须回答：这一轮我打脸了哪几条之前的结论？一条都没打脸 = 本轮无效，重做。**

## 28. 反证大会（每两轮做一次，形式固定）

对**每条你声称已完成**的项目：

1. **写断言**：把"已完成"写成一句可证伪的话（例：`在 MySQL 上把列宽拖到 300px，刷新后仍为 300px`）。
2. **设计破坏实验**：想三种让这句话变假的方式（刷新页面 / 切标签再回来 / 重启 / 换表 / 换库 / 缩窄窗口）。
3. **执行并计时**：限时 3 分钟出结果。
4. **结论三选一**：`成立（附证据）` / `不成立（附证据 + 缺陷 ID）` / `未验证（说明为何做不到，不算完成）`。
5. 凡"成立"的，下一轮换角度再打一次（不同库 / 不同窗口 / 不同入口）。

**规则：任何断言连续两轮未被独立复现，直接降级为"未完成"。**

## 29. 定量门槛（不达标不许写"完成"）

| 指标 | 门槛 |
|---|---|
| 每功能用例 | 连续 3 次 PASS + 重启后 1 次 PASS，证据文件落盘 |
| 入口覆盖率 | 菜单/Ribbon/右键/工具栏/对话框按钮 **100%** 点过，死入口 = 0 |
| 写操作侧效 | 100% 经 DB 侧反查一致（抽样需写明方法与比例） |
| 异常路径 | 每模块 ≥3 条异常用例通过 |
| 环境矩阵 | 3 种 DPI × 5 种尺寸 × 4 种数据库，无崩溃无错乱 |
| 控制台 | 0 未捕获异常、0 ACL/CSP 报错（附 Console 截图） |

**缺一项即整体判定「未完成」，不允许按比例折算。**

## 30. 禁止词表（出现即自我打回重写）

禁止：`应该` `大概` `基本` `差不多` `理论上` `看起来` `已修复` `已完成` `已验证` `全部通过`（无证据时）`影响不大` `可以接受` `已知问题（无后续）` `后续优化` `测试环境限制（未实际运行）` `受环境限制未验证` `我确认过` `我已经检查了`

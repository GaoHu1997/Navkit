# 驱动下载来源政策与待办

日期：2026-11-07。背景：驱动管理中部分数据源此前无法直接下载驱动；dbx 方案落地后重新盘点来源覆盖。
更新：2026-11-07 政策收紧——dbx 降级为一次性镜像来源，在用驱动将迁移到自有仓库托管。

## 一、政策：不在本仓库托管驱动，只用别人的

1. **本仓库与发布源码不保存任何驱动二进制**（JAR / DLL / MSI / ZIP）。仓库内只保存
   "URL + 大小 + SHA-256"固定指纹元数据（几百字节）；驱动文件由应用运行时下载到
   用户机器的数据目录（`data/managed-drivers/`，不入库、不进发布包）。
2. **允许的来源**（必须 HTTPS 直链 + 固定 SHA-256 校验，绝不执行安装器、绝不自动接受许可）：
   - 厂商官方：Maven Central（IBM jcc、Trino、达梦等 26 个托管 JDBC）、GBase 官方 CDN、
     星环官方 COS（Inceptor/ArgoDB 8.37.3）、GitHub Releases（DuckDB ODBC）、
     Oracle 官网现代直链（23.26 Basic+ODBC）、Snowflake 官方库（MSI 只下载不安装）；
   - 自有仓库托管（目标态）：在用驱动不得长期依赖他人仓库运行时获取。dbx
     （`t8y2/dbx`）固定提交 `71ce0349…` 仅作为**一次性镜像来源**，镜像已落位
     `tools/driver-mirror/dbx-71ce0349/`（大小/SHA-256 已核），待发布到自有仓库后
     切换下载 URL（固定指纹不变）。切换前运行时暂用 dbx 直链。UI 保留第三方溯源说明；
     原包许可/签名保留，dbx 自身许可不套用到专有驱动内容；
     连接层 TLS 不静默降级、扩展参数要求走自定义 JDBC。
3. **没有可核验外部来源的数据源**：保持"需手动获取"状态并记入本文待办，
   等待来源出现再接入；不自建托管、不伪造下载成功、不打开网页代用户接受许可。

## 二、现状盘点（2026-11-07 源码）

- 目录 35 个 ODBC 数据源 + H2：33 个有直链下载路径（官方来源 30 + dbx 3；
  dbx 为过渡期运行时来源，待切自有仓库托管）；
  H2 / DuckDB / Oracle / Snowflake 为独立路径。
- 无下载入口的仅剩两个入口型数据源，**属设计使然、不算缺口**：
  - 通用 ODBC（`odbc`）：本就没有唯一驱动，用户任选已安装驱动 / DSN；
  - 通用 JDBC（`jdbcx`）：用户自配 JAR；驱动管理对话框中隐藏（`DriverManagerDialog.ts` 分组过滤）。

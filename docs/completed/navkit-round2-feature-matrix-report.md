## 1. MySQL 8.0.46（深度实测：11 项功能 + 2000 万行性能）

连接 `R2-MySQL`（localhost:3306 / root）→ 测试连接返回 **8.0.46**；元数据 5 库读取正常。

### F1 数据类型覆盖 ✅（1 项显示缺陷）
- 28 列全类型建表写入（174ms），网格读回 **27/28 正确**
- **缺陷 D1：POINT 网格显示 NULL**（库内 ST_AsText = POINT(1 2)，与第一轮一致）

### F2 网格 CRUD ✅（三项全过 + 库侧复核）
- 增：网格「+」插行可提交
- 改：表单视图 val 100→777 提交，库侧=777（**关闭 NavKit 进程后复核仍为 777**）
- 删：选中行→删除记录→提交，COUNT 2→1
- 易用性：D3 未选中行删除静默无效；D4 表单视图删除不稳定

### F3 数据生成 ✅
- 500/500 行、错误 0、0.1s（≈5000 行/s）；参数化批量 INSERT；库侧 12800→13300 行

### F4 运行 SQL 文件 ✅
- 5004/5004 语句、错误 0、82.3s、影响 5000 行
- **缺陷 D11（高）**：含 `CREATE DATABASE/USE` 的文件被拒绝（"SQL 不能改变数据库/身份/服务器授权范围"）

### F5 转储 SQL 文件 ✅（P0 缺陷 D7）
- 22MB / 10 表 / 128,500 INSERT
- **缺陷 D7（严重）**：`DROP/INSERT` 带源库名而 `CREATE TABLE` 不带——导入到其他库时**误删源库同名表**（实测：verify_r2 导入后源库 t_copy1 被删空）

### F8 数据导出 ✅ / F9 数据导入 ✅
- 导出：10 CSV，行数与库一致（12800/13300）
- 导入：2000 行 CSV → t_copy1，100%，值正确

### F6 数据备份/还原 ✅（UI 缺陷 D8）
- 备份 122,700 行 / 20.14MB；还原重放后行数与备份时点一致（数据确实恢复 ✅）
- **缺陷 D8**：还原 UI 进度停滞、无完成提示

### F7 数据字典 ✅（P7 复现）
- 工具 → 数据字典（5 步向导，Word/PDF/HTML/Markdown/Excel 五格式）
- 12 表 MD 6.8KB；**P7 反斜杠文件名缺陷复现**（文件落在上级目录）

### F10 数据同步 ✅（D9/D10）
- 同构 navkit_r2.t_copy9 → navkit_r2_copy：12800 行，COUNT/SUM 一致
- **D9**：目标连接尝试 root@::1（IPv6）被拒，需 DBA 建 'root'@'::1'
- **D10**：自动建表类型膨胀 int→BIGINT、decimal(12,2)→DECIMAL(65,20)

## 2. MySQL 性能测试（50 表 / 20,210,000 行 / 单表 250 万）

数据集 big_1..8 各 250 万行 + small_1..42 各 4762 行；SQL 文件 1.21GB / 20,310 语句。

| 场景 | 数据量 | 耗时 | 吞吐 | 判定 |
|---|---|---|---|---|
| 运行 SQL 文件 | 20,210,000 行 / 1.21GB | 990.3s | **20,408 行/s** | ✅ |
| 转储 SQL 文件 | 全库 3.54GB | 183s | 11 万行/s | ✅ |
| 数据备份 | 全库 3.54GB | 276s | 7.3 万行/s | ⚠️ **完成时 OOM**（P2 复现） |
| 数据字典 | 50 表 28KB | <5s | — | ✅ |
| 导出 CSV | 250 万行 145MB | ~25s | 10 万行/s | ✅ |
| 导入 CSV | 250 万行 | ~200 万行处 | 11,700 行/s | ⛔ **OOM + 长事务全回滚** |
| 大查询 | 250 万聚合 12.6s；2000 万 COUNT | ✅ | — | ✅ |
| 同构同步 | 12,800 行 | ~10s | — | ✅ |

**P2 内存缺陷两次 OOM 复现（dmesg 实证）**：

2. 250 万行 CSV 导入至 ~200 万行 RSS 2.30GB 被 OOM，**长事务未提交 → 数据全丢**

## 11.3 第二轮缺陷清单（按严重度）

### 严重
| 编号 | 问题 |
|---|---|
| **P2-R** | 大任务内存 OOM：3.54GB 备份完成时 RSS 2.39GB 被 OOM；250 万行 CSV 导入 ~200 万行处 RSS 2.30GB 被 OOM 且**长事务全回滚（数据全丢）**——dmesg 实证两次 |
| **D7** | 转储写死源库名（DROP/INSERT 带名、CREATE 不带），导入他库**误删源表**（实测） |
| **D11** | 运行 SQL 文件拒绝含 CREATE DATABASE/USE 的文件，无指引 |
| **D16** | 查询页被隐式事务锁死：「事务/活动命名空间…此次没有发送」，Kill 服务端连接无效，需重启；TiDB/达梦/MariaDB 复现 |
| **D15** | **安全问题**：新建连接密码留空 + 保存密码勾选时发送 keystore 中其他连接的密码（TiDB 实证） |

### 中
D13（PG 仅结构转储空壳文件）、D14（同步向导回退重置连接）、D17（TiDB READ ONLY 语法）、D19（SQL Server 备份未实现）、D9（::1 IPv6 无回退）、D8（还原进度停滞）、P5-R（达梦多语句未修复）、金仓默认库问题

### 低
D1/D12/D18（类型显示 NULL 面）、D10（同步建表类型膨胀）、D3/D4（删除交互）、D5（树缓存）、D6（无障碍树退化×3）、P7-R（反斜杠文件名）、P8-R（输入拼接）

## 11.5 结论

1. **可用性**：12 数据源连接全部成功；MySQL/PG 功能矩阵基本全通；工具链在 MySQL 上全链路可用。
2. **性能**：2000 万行规模导入 20,408 行/s、转储 11 万行/s、导出 10 万行/s、聚合 12.6s——达标；**备份完成时与 CSV 大导入被 P2 内存缺陷阻断**，为最高优先修复项。
3. **可靠性短板**：OOM×2、无障碍树退化×3、查询页锁死（D16）。
4. **修复优先级**：①P2 内存（流式写盘+分批提交）②D7 转储库名 ③D15 密码泄露 ④D16 查询页会话 ⑤D17 TiDB 方言 ⑥达梦 P5。
